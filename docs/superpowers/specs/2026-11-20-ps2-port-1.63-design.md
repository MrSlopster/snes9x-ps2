# Snes9x 1.63 PS2 Port — Design Spec

Date: 2026-11-20
Author: MrSlopster (via agent)
Status: Approved (design discussion 2026-11-20)

## Goal

Port the Snes9x **1.63** upstream core (github.com/snes9xgit/snes9x, master @ 1bcc369,
2026-09-24) to the PlayStation 2, replacing the 2011 BoGanon fork
(github.com/BoGanon/snes9x, Snes9x 1.53 base) as "the PS2 version".

Success criteria:

1. `make -C ps2` produces a working `snes9x.elf` in the Docker toolchain
   (`ghcr.io/ps2dev/ps2dev` + ps2sdk), with zero build errors and no new warnings.
2. The port uses the modern core APIs (sound driver base class, controls API,
   renderer hooks) with no edits to core emulation logic.
3. All 15 years of upstream accuracy fixes (PPU, APU, DSP, SA-1, MSU-1, …) come
   along for free; the fork's old core-side hacks are not carried over.
4. EE-targeting performance practices from the fork (compiler flags, memory
   placement, DMA-friendly buffers) are carried over where they still apply.

## Non-goals (deferred)

- The old `BoGanon/interface` GUI library: it pins ps2sdk libs that no longer
  exist (`SMSCDVD`, `inputx`, `padx`, `mf`). Modernizing it is a separate
  project. v1 runs with a minimal front-end.
- Netplay, movie playback, cheats UI (cheat engine in the core still works).
- VU/DMA hardware acceleration of rendering (documented as follow-up hooks).

## Architecture

- Base tree: upstream master as the base commit of a new repo
  (`snes9x-1.63-ps2/`); the 2011 fork is kept untouched as reference.
- All port code lives in a new `ps2/` directory, mirroring how `unix/`, `gtk/`,
  `win32/` are structured.
- Core files receive, at most, `#ifdef`-free build-flag / `port.h` config
  changes (`PIXEL_FORMAT RGB565`, `RIGHTSHIFT_*_IS_SAR`, MIPS-endianness).
- Repo layout of the port:

```
ps2/
  Makefile            ps2sdk-style makefile (Makefile.pref, Makefile.eeglobal)
  ps2_main.cpp        EE entry point + init sequence + main loop
  ps2_video.cpp/.h    GS framebuffer output (S9xInitUpdate/S9xDeinitUpdate)
  s9x_sound_driver_audsrv.hpp/.cpp
                      audsrv backend implementing common/audio S9xSoundDriver
  ps2_controls.cpp/.h libpad/libmtap input -> snes9x controls API
  ps2_dirs.cpp/.h     S9xGetDirectory/GetFilename/snapshot streams (fileXio)
  ps2_settings.cpp    Settings defaults (unix-port equivalent)
```

## Port surface (1.63 core API)

Functions the port must provide (referenced from unix port + libretro core):

- `S9xInitUpdate`, `S9xDeinitUpdate(width, height)`, `S9xContinueUpdate`
- `S9xSyncSpeed` (frame pacing; fork-style custom pacing possible later)
- `S9xMessage`, `S9xExit`
- `S9xGetDirectory`, `S9xGetFilename`, `S9xGetFilenameInc`
- `S9xOpenSnapshotFile`, `S9xCloseSnapshotFile` (gz streams via zlib)
- `S9xAutoSaveSRAM`
- `S9xParsePortConfig` (only if CONFFILE_SUPPORT; v1: not used)
- `S9xHandlePortCommand`, `S9xPollButton`, `S9xPollAxis`, `S9xPollPointer`
  (stub: no unpolled devices in v1)
- Sound: implement `S9xSoundDriver` (common/audio/s9x_sound_driver.hpp):
  `init, deinit, open_device(playback_rate, buffer_size), start, stop,
   write_samples, space_free, buffer_level`; register via `S9xInitSound` and
  set `S9xSetSoundMute` appropriately.
- Controls: `S9xReportControllers` sets up the controller port layout; pad
  state is fed via the controls API each frame (libretro core is the reference
  for exact calls: `S9xReportButton` / direct `P1` joypad writes).

Init sequence (mirrors unix `main()`):

```
memset(&Settings, 0, sizeof(Settings)); apply unix-style defaults;
Memory.Init(); S9xInitAPU();
S9xInitSound(rate); S9xSetSoundMute(TRUE);
S9xReportControllers();
Memory.LoadROM(path); Memory.LoadSRAM(...);
S9xCheatsEnable();
CPU.Flags saved/restore; Settings.StopEmulation = FALSE;
video init (GS); sound driver start;
loop { S9xMainLoop(); poll pads; }
```

## Video

- Core renders RGB565 (`PIXEL_FORMAT RGB565`), no `GFX_MULTI_FORMAT`
  (single-format build: less code, faster).
- `GFX.Screen` buffer allocated by the core (S9xGraphicsInit) — the port only
  blits it to GS.
- GS setup: NTSC non-interlaced 640x448 framebuffer; SNES frame (256/512 x
  224/239) uploaded as a 16-bit texture (PSM_CT16S) via DMA and drawn
  stretched to the framebuffer.
- Framebuffer and texture buffers aligned for DMA (16-byte min; prefer
  256-byte for transfer efficiency); uncached staging pointer only where it
  measurably wins.

## Audio

- audsrv (modern ps2sdk `libaudsrv`), 31950 Hz input rate → 48000 Hz output,
  stereo 16-bit.
- Driver class mirrors the SDL/OSS drivers in `common/audio/` so the modern
  sync/throttle logic (S9xSyncSpeed + buffer_level) works unmodified.

## Input

- `libpad` for 2 controller ports, `libmtap` when a multitap is present.
- Map PS2 pad → SNES joypad: D-Pad, Square/Cross/Circle/Triangle →
  B/A/X/Y, L1/R1 → L/R, Start, Select.
- Analog sticks optional (mouse fallback via S9xPollAxis is out of scope v1).

## Filesystem layout on PS2

- Base dir: `mass:/snes9x` when USB is available, else `mc0:/snes9x`.
- Subdirs: `roms/`, `srm/`, `saves/`, `screenshots/`, `spc/`, `cheats/`,
  `patch/`, `bios/` (matching core dir types).
- ROM picked from a simple, fixed search order (v1): 1) ROM path passed in
  argv; 2) first ROM in `roms/`. No browser UI in v1.

## Build

- ps2sdk-style Makefile with `Makefile.pref` / `Makefile.eeglobal`.
- Core object list mirrors unix port's file list (verify against 1.63: new
  files `bml.o`, `cheats2`→`cheats_(old/new)` renames, `tileimpl-*.o`,
  `sha256.o`, `seta018.o`, …; no `i386/`, no `logger`).
- Flags: `-mtune=r5900 -mhard-float -msingle-float -fsingle-float-constant
  -mfused-madd -ffast-math -fno-mips16`, `RIGHTSHIFT_IS_SAR`, `-O3` baseline,
  `-Ofast` evaluated.
- Libraries: `-ldma -lpacket -lgraph -ldraw -laudsrv -lpad -lmtap -lfileXio
  -lmc -lz` (+ zlib built inside the image or vendored in `unzip/`-style).
- Build loop runs in Docker with the repo mounted; produce `ps2/snes9x.elf`.

## Error handling

- Init failures print to stdout (ps2link-visible) and set
  `Settings.StopEmulation = TRUE` semantics / exit cleanly.
- ROM load failure: print searched paths, fall back to clean shutdown.
- Sound device failure: mute + continue (video-only emulation), matching unix
  behavior.

## Testing / verification

- Docker build to a clean `.elf` is the acceptance gate.
- Hook-usage cross-checked against `libretro/libretro.cpp` and
  `unix/unix.cpp` during implementation.
- Hardware testing instructions shipped in `ps2/README.md` (ELF + dir layout +
  boot methods: ps2link, USB). Frame-rate comparison vs. 2011 fork is a
  hardware-test item we cannot perform here — documented as a known risk.

## Risks

1. **Performance**: 1.63 core is heavier than 1.53. Mitigation: EE flags,
   single pixel format, DMA-friendly buffers; hardware profiling is a
   follow-up.
2. **ps2sdk API drift** (audsrv init, pad API, libc differences): resolved
   iteratively inside the Docker build loop.
3. **Renderer memory footprint** (tileimpl templates): PS2 has 32 MB, 16 MB
   usable heap after EE kernel; expected fine, verified at link/load time.
